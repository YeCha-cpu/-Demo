# 阶段 4 · 蒙太奇制作与接入指南

> 动画蓝图解决"走跑跳蹲"，蒙太奇解决"攻击翻滚"。
> **没有蒙太奇，攻击动作永远播不出来** —— AnimGraph 里的 Slot 是空的，没人往里送动画。

---

## 0. 蒙太奇在链路里的位置

```
按左键
  ↓
GA_LightAttack 激活 → PlayMontageOrSkip(Segment->Montage)
  ↓
蒙太奇开始播放，抢占 AnimGraph 里的 [Slot 'DefaultSlot']
  ↓                                    ↑
动画播到 Notify 位置                      └── 覆盖移动动画，播完自动交还
  ↓
AnimNotify → SendGameplayEventToActor
  ↓
GA 的 WaitGameplayEvent 回调 → 开伤害检测 / 推进连段 / 结束能力
```

**关键点**：蒙太奇不只是"播个动画"。**伤害判定、连段推进、无敌帧全靠蒙太奇上的 Notify 驱动**。
所以蒙太奇做得好不好，直接决定战斗手感。

---

## 1. 步骤 1 · 把 `DefaultSlot` 注册到骨架（一次性）

先确认骨架里有这个插槽，否则蒙太奇和 AnimGraph 都选不到它。

**Window → Anim Slots**（在动画编辑器的菜单栏里）

| 检查项 | 期望 |
|---|---|
| Slot 列表里有 `DefaultSlot` | ✅ 有就跳过这一步 |
| 没有的话 | 点工具栏 **`Add Slot`** → 名字填 `DefaultSlot`，Group 用 `DefaultGroup` |

> 💡 UE5 的 Mannequin 骨架默认就带 `DefaultSlot`，多半不用手动加。
> 但如果你换了自定义骨架，这一步必须做 —— 漏了的表现是"蒙太奇在蒙太奇编辑器里
> 预览正常，一进游戏就不播"。

---

## 2. 步骤 2 · 从动画序列创建蒙太奇

在 Content Browser 里**右键点一个动画序列** → **Create → Create AnimMontage**

命名规范（和 `DA_AttackModule` 里的字段对应）：

| 用途 | 命名示例 |
|---|---|
| 轻击 5 段 | `AM_Light_01` ~ `AM_Light_05` |
| 切手技 | `AM_ComboTransition` |
| 蓄力起手 | `AM_Heavy_ChargeStart` |
| 蓄力循环（可选） | `AM_Heavy_ChargeLoop` |
| 重击释放（3 段） | `AM_Heavy_Release_01` ~ `03` |
| 闪避 | `AM_Dodge_Fwd` / `AM_Dodge_Bwd` / `AM_Dodge_L` / `AM_Dodge_R` |

建议放在 `Content/_My/Animation/Montages/`。

## 3. ★ 步骤 3 · 调整混合时间（最容易忽略，影响最大）

**这一步不做，攻击动画会看起来"只是微微动了一下"。**

`UAnimMontage` 的构造函数把 `Blend In` 和 `Blend Out` 各默认设成 **0.25 秒**
（引擎源码 `AnimMontage.cpp:76-77`）。对一段 0.6 秒的攻击动画来说，这意味着：

```
0.00 ──── 0.25 ── 0.35 ──────────── 0.60 秒
  │  淡入   │ 打满 │      淡出        │
  │←0.25 秒→│0.1秒 │←──── 0.25 秒 ───→│
   ↑ 这段时间角色大半还保持着站姿/跑姿
```

真正"打满"的只有中间 **0.1 秒**。所以你会看到：按了攻击键，人物动了一下就回去了。

### 更糟的情况：淡入还没走完就先淡出

淡出的触发点是 `AnimMontage.cpp:2633`：

```cpp
// PlayTimeToEnd = 动画全长 - 当前位置
// BlendOutTriggerTime 默认 = BlendOut.BlendTime（也就是 0.25 秒）
if (PlayTimeToEnd <= BlendOutTriggerTime) { Stop(...); }   // 开始淡出
```

按这个公式，**淡出在 `位置 = 全长 - 0.25` 秒时就开始了**。对一段 0.37 秒的动画：

```
0.00 ─────── 0.12 ──── 0.25 ──────── 0.37 秒
  │  淡入 48%  │        │            │
  │           ↑ 淡出从这里开始        │
  │           而淡入要到 0.25 才走完   │
```

**淡入和淡出重叠了** —— 动作的混合权重永远达不到 1.0，角色只会做出一个"半吊子"的
模糊动作。这正是"人物只是微微动了一下"的直接原因。

**结论**：当 `淡入 + 淡出 > 动画全长` 时，这段动画基本废了。
本工程的轻击动画只有 0.33~0.50 秒，用默认值必然踩中。

**这不是 bug，是引擎默认值不适合短促的攻击动作。**

**修法**：打开每个攻击蒙太奇，在 Details 面板里找：

| 分组 | 字段 | 建议值 |
|---|---|---|
| `Blend In` | `Blend Time` | **`0.05` ~ `0.1`** |
| `Blend Out` | `Blend Time` | **`0.1` ~ `0.15`** |

改完之后的对比（以 0.37 秒的 `AM_Light_01` 为例）：

| | 淡入 | 淡出 | 淡出触发点 | 满强度时长 |
|---|---|---|---|---|
| 默认 | 0.25 | 0.25 | t = 0.12 秒 | **负数 —— 永远到不了满强度** |
| 调整后 | 0.05 | 0.10 | t = 0.27 秒 | 0.05 → 0.27 秒，**约 0.22 秒** |

> 💡 还可以再调一个字段：**`Blend Out Trigger Time`**。
>
> | 值 | 含义 |
> |---|---|
> | `-1`（默认） | "在动画结束前 `BlendOut.BlendTime` 秒开始淡出" —— **这就是上面重叠问题的来源** |
> | `≥ 0`（比如 `0.05`） | 淡出推迟到"只剩 0.05 秒"时才触发，动作能更完整地播完 |
>
> 设成非负值后，淡出会延续到动画结束**之后**才收尾，视觉上反而更自然 ——
> 相当于"动作完整做完，再慢慢交还给移动动画"。

> 💡 攻击动作本来就该"啪"地切入，不该慢悠悠淡入 —— 玩家按键和角色出招之间
> 的心理预期只有一两帧。慢速淡入会让人觉得"按键不跟手"。

> 💡 唯独**闪避**可以留长一点（0.1~0.15），翻滚需要一点惯性感。

**代码会替你检查**：`PlayMontageOrSkip()` 里有一条自动体检 ——
当 `淡入 + 淡出 > 动画全长的 50%` 时会在日志里打 Warning，直接告诉你哪个蒙太奇有问题。

```
LogRPG_Ability: Warning: [GA_LightAttack_C_0] 蒙太奇 AM_Light_01 的混合时间过长：
淡入 0.25 + 淡出 0.25 = 0.50 秒，而动画全长只有 0.62 秒。
角色大部分时间都处于混合状态，看起来会像只动了一下。
修法：打开该蒙太奇资产的 Details，把 Blend In / Blend Out 各调到 0.05~0.1 秒
```

## 4. 步骤 4 · 加 Slot 段落

打开蒙太奇资产 → 底部时间线区域 → **在 Montage 轨道上右键 → `Add Slot`**

| 字段 | 值 |
|---|---|
| Slot Name | **`DefaultSlot`** |

已有默认 Slot 段落时不用再加。要改名：**右键那个 Slot 段落 → `Slot name`**。

> ⚠️ **这个字符串必须和 AnimGraph 里 Slot 节点的 `Slot Name` 完全一致**（区分大小写）。
> 不一致时**不会报任何错**，只是动画不播 —— 这是最难查的坑之一。

保存后确认时间线上有一整条覆盖整个动画长度的 Slot 段落（如果只覆盖前几帧，
后面的部分不会被蒙太奇接管，表现为"打到一半动作突然弹回跑步"）。

---

## 5. 步骤 5 · 配置 Notify

在时间线的 **Notifies 轨道**上右键 → `Add Notify State` / `Add Notify`，
从列表里选下面这几个（都用 `RPG` 前缀搜索）：

| 编辑器里的名字 | 类型 | 广播的 GameplayEvent |
|---|---|---|
| **`RPG 攻击判定窗口`** | Notify **State** | `Event.Combat.AttackWindow.Open` / `.Close` |
| **`RPG 连段衔接窗口`** | Notify **State** | `Event.Combat.ComboWindow.Open` / `.Close` |
| **`RPG 无敌帧`** | Notify **State** | `Event.Character.Invulnerability.Begin` / `.End` |
| **`RPG 攻击结束`** | Notify（单点） | `Event.Combat.AttackEnd` |

### `RPG 攻击判定窗口` 的参数

| 字段 | 说明 |
|---|---|
| `Attack Tag` | 这一段的标签，如 `Ability.Attack.Light.01`。**只用于日志区分**，不填也能跑 |
| `Override Trace` | 默认**不勾** —— 用攻击模组 DA 里的检测配置 |
| `Trace Source` | 勾了 Override 才生效：双手骨骼 / 武器刀锋 / 发射物 |
| `Trace Radius` | 勾了 Override 才生效，默认 30 |
| `Socket Start` / `Socket End` | 勾了 Override 才生效。留空则用 DA 里的默认 Socket |

> 💡 **只有大范围横扫这类特殊招式才需要勾 Override**。普通攻击统一用 DA 的配置，
> 改平衡时只动一个地方。

其余三个 Notify **没有任何参数** —— 加上就行。

## 6. 步骤 6 · 各动作的 Notify 布局

时间位置用**百分比**表示（因为各人手上的动画长度不一样）。
调参时按"整段动画长度的百分之几"去拖，比记绝对秒数靠谱。

### 5.1 轻击第 1~4 段

```
0%        25%         45%        55%          85%      95%  100%
├─────────┼───────────┼──────────┼─────────────┼────────┼────┤
│  起手    │  判定窗口  │  收招    │  衔接窗口    │        │    │
│         │▓▓▓▓▓▓▓▓▓▓▓│          │▓▓▓▓▓▓▓▓▓▓▓▓▓│        │    │
│         │  攻击判定   │          │  连段衔接    │        │ 结束│
```

| Notify | 起始 | 结束 |
|---|---|---|
| `RPG 攻击判定窗口` | 25% | 45% |
| `RPG 连段衔接窗口` | 55% | 85% |
| `RPG 攻击结束` | — | 95%（单点） |

### 5.2 轻击第 5 段（收尾段）

同上，但 **不加 `连段衔接窗口`** —— 第 5 段是终结技，打完就结束，不能无限连。

### 5.3 蓄力起手 `AM_Heavy_ChargeStart`

**什么 Notify 都不加。** 它只是个"摆姿势"的起手动画，播完就停住等玩家松手。

### 5.4 蓄力循环 `AM_Heavy_ChargeLoop`（可选）

**加一个 `RPG 攻击判定窗口` 吗？不加。**

| 设置 | 值 |
|---|---|
| Section 的 `Next Section` | **指向自身**（这样才会循环） |
| Notify | 无 |

### 5.5 重击释放 `AM_Heavy_Release_01~03`

```
0%     30%              55%            80%     95%  100%
├──────┼────────────────┼──────────────┼───────┼────┤
│ 蓄力  │   判定窗口      │              │       │    │
│      │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│              │       │结束│
```

| Notify | 起始 | 结束 |
|---|---|---|
| `RPG 攻击判定窗口` | 30% | 55% |
| `RPG 攻击结束` | — | 95%（单点） |

> 重击**没有衔接窗口** —— 蓄力重击是终结技，不该能接下一段。
> 这正好对上"切手技"的定位：想变招就在轻击连段里按右键，不是打完重击再按。

### 5.6 切手技 `AM_ComboTransition`

| Notify | 起始 | 结束 |
|---|---|---|
| `RPG 攻击判定窗口` | 25% | 50% |
| `RPG 攻击结束` | — | 95%（单点） |

### 5.7 闪避 `AM_Dodge_*` ★ 唯一带无敌帧的

```
0%    15%              60%         90%   100%
├─────┼────────────────┼───────────┼─────┤
│起跳  │    无敌帧       │   落地     │     │
│     │▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│           │     │
```

| Notify | 起始 | 结束 |
|---|---|---|
| `RPG 无敌帧` | 15% | 60% |
| `RPG 攻击结束` | — | 95%（单点） |

> ⚠️ **无敌帧的起止点必须对着"脚离地"和"落地前"这两帧调**，
> 不能拍脑袋。
>   · 开太晚 → 玩家明明已经翻出去了还是被打到，感觉判定不公
>   · 关太早 → 翻滚后半段暴露，闪避收益下降
>   · 关太晚 → 无限翻滚规避伤害，战斗失去张力

## 7. 步骤 7 · 填进 `DA_AttackModule`

打开 `Content/_My/Data/DA_AttackModule_*`，把刚做的蒙太奇填进去：

| DA 里的字段 | 填什么 |
|---|---|
| `Light Attacks[0..4].Montage` | `AM_Light_01` ~ `AM_Light_05` |
| `Heavy Attack.Charge Start Montage` | `AM_Heavy_ChargeStart` |
| `Heavy Attack.Charge Loop Montage` | `AM_Heavy_ChargeLoop`（可选） |
| `Heavy Attack.Levels[0..2].Release Montage` | `AM_Heavy_Release_01` ~ `03` |
| `Combo Transition Montage` | `AM_ComboTransition` |

**闪避蒙太奇不在 DA 里** —— 它在 `GA_Dodge` 蓝图上的 `Dodge Montage` 字段。

> 留空不影响逻辑：GA 会走模拟时序分支，连段、伤害、耐力照常执行。
> 所以你可以一段一段地接，接上一段就能看到一段的真实动画。

## 8. 自动体检 —— 不用肉眼对时间轴

`DA_AttackModule` 现在带一份**蒙太奇 Notify 体检**（`URPG_AttackModuleData::IsDataValid`）。
它会把每个攻击蒙太奇上的三个关键 Notify 换算成百分比，配错了直接在 Content Browser 里标黄。

**怎么触发**：
- 右键 `DA_AttackModule_*` → **Asset Actions → Validate Assets**
- 或者编辑器启动时会自动校验一次
- 资产标黄后悬停（或点开 Message Log 的 Asset Check 分类）看详情

**能查出这几种**：

| 检查项 | 为什么 |
|---|---|
| `RPG 攻击结束` **位置 < 70%** | ★ 头号杀手。GA 会在那一帧结束能力并停掉动画 → 连段中途断掉、动作只播了个开头 |
| 缺少 `RPG 攻击结束` | GA 退化成"蒙太奇播完才结束"，后摇偏长 |
| 缺少 `RPG 攻击判定窗口` | 这一刀不会造成任何伤害 |
| 非最后一段缺少 `RPG 连段衔接窗口` | 这一招接不下去 |
| 最后一段**却有**衔接窗口 | 终结技可以无限连 |

**蓄力起手 / 蓄力循环用的是反过来的规则**：

| 检查项 | 为什么 |
|---|---|
| 有 `RPG 攻击结束` | 起手姿势刚摆好能力就结束 → 蓄力形同虚设 |
| 有 `RPG 攻击判定窗口` | 每次摆蓄力姿势都白送一次伤害 |
| 有 `RPG 连段衔接窗口` | 蓄力中会意外接出下一段 |

> ⚠️ 这两套规则是**分开**的，不能混用。早先的版本把起手动画按攻击动作来查，
> 结果是"资产配对了反而被标黄"，而照着提示改恰恰会把蓄力搞坏 ——
> **带错方向的校验比不检查更糟。**

**输出长这样**（只在有问题时才标黄，全对的蒙太奇不会刷屏）：

```
第 2 段轻击（AM_Light_02，全长 0.33 秒）
  ✗ `RPG 攻击结束` 在 6% 处，**太靠前** → GA 会在这一帧结束能力并停掉动画，
    表现为连段中途断掉、动作只播了个开头。拖到 95% 附近
  Notify 实际位置：判定窗口 25%→45%｜衔接窗口 0%→80%｜攻击结束 6%
```

> 💡 最后那行"实际位置"是重点：把 5 段轻击的体检结果并排一看，
> 就能立刻发现"第 1 段的窗口在 81%，第 2 段却在 6%"这种不一致 ——
> 而**这种不一致才是手感忽好忽坏的真正来源**，单看某一段是看不出来的。

## 9. 验收

PIE，逐项确认：

| 检查项 | 期望 | 出问题时看这里 |
|---|---|---|
| 按左键 | 挥击动作完整播放，播完自动回移动动画 | Slot 名字是否一致 |
| 连按左键 | 第 1 段后摇里接上第 2 段，动作不重叠 | 衔接窗口的位置 |
| 打 5 下 | 第 5 段后停住，不会再接 | 第 5 段不该有衔接窗口 |
| 空挥 | **不该有伤害**（判定窗口外挥刀无伤害） | 判定窗口的位置 |
| 按住右键不放 | 摆起手姿势 → 保持 → 耐力持续下降 | `AM_Heavy_ChargeStart` 有没有误加 Notify |
| 蓄力 2 秒后松手 | 播第 3 段的释放动画 | DA 里 Levels 的门槛时间 |
| 蓄力中按左键 | 蓄力被打断，接上轻击 | `CancelAbilitiesWithTag` |
| 翻滚 | 有无敌帧，被击中时**不掉血** | 无敌帧 Notify 的起止点 |
| 攻击中按住 Shift | 不切跑步动画（蒙太奇覆盖全身） | Slot 是否接在状态机**之后** |

### 验证 Notify 真的触发了

控制台 `Log LogRPG_Animation Verbose` 和 `Log LogRPG_Combat Log`，攻击时应该看到：

```
[BP_RPG_Player_C_0] 攻击判定窗口开启（Ability.Attack.Light.01）
轻击第 1 段（倍率 1.00，耐力 8.0）
[BP_RPG_Player_C_0] 攻击判定窗口关闭
衔接窗口开启
轻击第 2 段（倍率 1.15，耐力 8.0）
```

**没有第一行** = 蒙太奇里的判定窗口 Notify 没加上，或者 Slot 名字不对导致蒙太奇压根没播。

## 10. 常见问题排查

| 症状 | 最可能的原因 |
|---|---|
| **按了攻击键，人物只是微微动了一下** | **蒙太奇的 `Blend In` / `Blend Out` 默认各 0.25 秒，把短动画吃掉了** —— 见步骤 3 |
| 攻击动作看着"没打完就收了" | 同上；或者衔接窗口开太早，被下一段接走（看下面的诊断日志） |
| 攻击时角色不动，但伤害/耐力都正常 | GA 走的是模拟时序分支 —— DA 里那个 `Montage` 字段是空的 |
| 蒙太奇在编辑器里预览正常，游戏里不播 | Slot 名字和 AnimGraph 里不一致（大小写敏感，不报错） |
| 动作播到一半突然弹回跑步 | 蒙太奇的 Slot 段落没覆盖整段动画长度 |
| 一直有伤害但看不到挥击 | 判定窗口的 Notify 加上了，但蒙太奇没播（Slot 问题） |
| 挥了刀但打不到人 | 判定窗口位置不对；或 `Trace Radius` 太小；或目标不在 `ECC_Pawn` 通道上 |

### 判断"动画太短"还是"被截断"：看日志

`GA_LightAttack` 会在每段开始时打出这一段的两个数字：

```
LogRPG_Combat: Log: [BP_RPG_Player_C_0] 轻击第 1 段（倍率 1.00，耐力 8.0，动画 AM_Light_01 0.62 秒）
LogRPG_Combat: Log: [BP_RPG_Player_C_0] ↳ 第 1 段实际播放 0.35 秒 / 全长 0.62 秒 —— 被下一段接走（衔接窗口开太早）
```

| 现象 | 结论 | 怎么修 |
|---|---|---|
| 实际播放 ≈ 全长 | 动画本身就这么短 | 换更长的动画资产 |
| 实际播放 ≪ 全长，且显示"被下一段接走" | 衔接窗口开太早 | 把 `RPG 连段衔接窗口` 整体往后挪 |
| 实际播放 ≈ 全长，但看着还是"没动" | 混合时间吃掉了 | 见步骤 3：调 `Blend In` / `Blend Out` |

**光靠眼睛分不出这两种情况**，所以我把数字打出来了。

### 切手技为什么之前打不出来（已修复）

根因是 GAS 的一个执行顺序陷阱 —— `CancelAbilitiesWithTag` **会先于** `ActivateAbility` 执行：

```
CallActivateAbility()                        (GameplayAbility.cpp:1020)
   ├─ PreActivate()                          ← :1022
   │     └─ ApplyAbilityBlockAndCancelTags() ← :999
   │           └─ CancelAbilities → 轻击的 EndAbility
   │                 └─ 摘掉 ActivationOwnedTags（Ability.Attack.Light 就在里面）
   └─ ActivateAbility()                      ← :1023
         ↑ 轮到这里时标签已经没了，分支判断永远是"蓄力"
```

原来的写法是"在构造函数里声明 `CancelAbilitiesWithTag`，然后在 `ActivateAbility`
里查标签判断该走切手技还是蓄力"—— 引擎先把轻击取消了，我们再去问"轻击在不在"，
答案永远是"不在"。而且**不报任何错**。

修法：`GA_HeavyAttack` 不再用声明式取消，改成在 `ActivateAbility` **开头**先读标签、
读完再显式调用 `ASC->CancelAbilities()`。

> 附带的好处：现在如果 `CommitAbility` 失败（耐力不够等），轻击**不会**被白白取消 ——
> 之前那种写法下，重击没放出来轻击却被打断了，连段会莫名其妙断掉。
