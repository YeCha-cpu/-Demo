## 1. 已修复：客户端无法激活输入能力

**完整分析见 [`ARCHITECTURE.md`](./ARCHITECTURE.md) §15。** 这里只留结论。

```
旧： RegisterInputAbilities(mappings)        ← 只在服务器的 HasAuthority 分支里调
        └─ 登记映射 + 逐个授予           ← 客户端永远拿不到映射表

新： RegisterInputAbilityMappings(mappings)  ← 两端都调（纯配置数据）
     GrantInputAbilities()                   ← 仅服务器
     RebuildInputTagHandleMap()              ← 客户端：从复制的 Spec 反查重建
        └─ 由 OnRep_ActivateAbilities() 触发
```

**顺带改掉的诊断缺陷**：原来"标签压根没绑能力"和"能力还没复制到"共用一句
`没有绑定任何能力`，但这两者的排查方向完全相反。现在拆成三条不同的警告，
而且**各自用独立的去重集合**（共用的话，客户端进场时先报一次时序问题，
那个标签就被永久标记，之后真的配错也再不会报警 —— 正好把拆分又抹掉了）：

| 情况 | 日志 | 该去改什么 |
|---|---|---|
| 映射表整张是空的 | `暂时无法激活：能力映射表还是空的` | 大概率只是启动时序（在等 PlayerState），重按即可；一直这样就查初始化 |
| 表里有别的、没这一条 | `没有绑定任何能力（映射表里已有 N 条，不含这一条）` | 去角色蓝图加 `Startup Abilities` |
| 表里有、但拿不到能力实例 | `已登记映射，但拿不到对应的能力实例` | 能力没复制到 / 服务器没授予 |

### 已知局限（写下来，别等踩到才发现）

| 局限 | 说明 | 什么时候会变成问题 |
|---|---|---|
| **两个输入标签映射到同一个 GA 类** | 服务器会授予两个独立 Spec，而客户端的索引重建是按类反查的（`FindAbilitySpecFromClass` 只返回第一个），两个标签会指向同一份实例 | 目前每个标签一个独立 GA 类，不会触发。**注册时会打一条 Warning 提醒** |
| 索引重建依赖 `OnRep_ActivateAbilities` 的触发时机 | 代码链路静态验证过，但"客户端第一次按键是否一定在它之后"没有实测 | 客户端进场后**第一次**按键可能落空（会报上面第三条警告，再按一次即可） |

## 2. ★ PIE 双客户端配置

### 2.1 设置（编辑器主工具栏，**Play 按钮旁边那个下拉箭头**）

| 设置项 | 值 | 说明 |
|---|---|---|
| **Number of Players** | `2` | Play 下拉菜单里直接有个数字框 |
| **Net Mode** | **`Play As Listen Server`** | Play 下拉 → `Net Mode` 子菜单里选 |
| 其余 | 保持默认 | 不需要勾 Dedicated Server（本项目不做 L3） |

> 💡 菜单里三个 `Net Mode` 选项的含义（引擎里的原话）：
> · `Play Standalone` —— 单机，不建服务器也不连
> · `Play As Listen Server` —— **编辑器自己既是服务器又是客户端**，再额外开 N-1 个客户端
> · `Play As Client` —— 编辑器只当客户端，后台给你起一个服务器

### 2.2 你会看到什么

会弹出 **2 个 PIE 窗口**：

| 窗口 | 角色 | `HasAuthority()` |
|---|---|---|
| 第 1 个 | **服务器 + 本地玩家**（主机） | ✅ true |
| 第 2 个 | **纯客户端** | ❌ false |

> ⚠️ **两个窗口都要操作**。这次验收的重点恰恰是**窗口 2**——
> 它才是那个之前"按什么都没反应"的那一端。
> 只在窗口 1 里打两下的测试，跟单机没有区别。

### 2.3 建议的窗口布局

`Window` 菜单可以切换 PIE 窗口的排布。两个窗口并排（Side by Side）
最方便观察"同一件事在两端看起来一不一样"。

## 3. 验收清单

> **每一项都要在 2 个窗口里各做一次。** 只在一端验证不算通过。
> 标 ⭐ 的是**这次修复直接覆盖的路径**，优先做。

### 3.1 输入与能力（⭐ 核心）

| # | 操作 | 两端各自的预期 |
|---|---|---|
| 1 | ⭐ 在**窗口 2**（客户端）按左键 | **打出轻击**（修复前：完全没反应） |
| 2 | ⭐ 连按左键 | 5 段连段正常衔接（不是"只有第一下"） |
| 3 | 窗口 2 按右键 | 蓄力重击，右下角蓄力条涨，松手归零 |
| 4 | 窗口 2 按 Alt | 闪避，有无敌帧 |
| 5 | 窗口 2 按 Shift / Space | 奔跑 / 跳跃，耐力条变化 |
| 6 | 两端同时攻击 | 互不干扰，各打各的 |

**日志检查**（窗口 2 的日志里应该有）：

```
LogRPG_Ability: 登记输入能力映射：5 条（客户端）
```

**修复前**这里会是"0 条"或者压根没有这一行，然后每次按键刷：
`输入标签 Input.Attack.Light 没有绑定任何能力`。
**修复后**这条警告**不应该再出现**。

### 3.2 伤害与表现

| # | 操作 | 预期 |
|---|---|---|
| 7 | 窗口 2 打敌人 | 敌人掉血；**两个窗口都能看到**敌人头顶血条下降 |
| 8 | 窗口 2 打敌人 | **两个窗口都能看到**伤害飘字（各自在各自屏幕上） |

> 💡 **飘字为什么两端都该有**：伤害由服务器判定，然后 `NetMulticast` 广播给所有客户端，
> 每个客户端各自把世界坐标投影到自己屏幕上（相机不一样，投影结果也不一样）。

### 3.3 死亡与重生

| # | 操作 | 预期 |
|---|---|---|
| 11 | 把窗口 2 的玩家打死 | **两个窗口**都能看到他倒下（布娃娃） |
| 12 | 等 3 秒 | 窗口 2 回到 PlayerStart、满血；**窗口 1 屏幕上他也回去了** |
| 13 | 复活后立刻按左键 | 能正常攻击（`State.Dead` 被摘干净了） |
| 14 | 复活后站一会儿 | 耐力**会恢复**（常驻被动被重启了） |
| 15 | 打死敌人 | 两个窗口都看到敌人倒地；敌人不重生（`Respawn Delay = 0`） |

> ⚠️ **第 12 项是这一阶段新加过代码的地方**：
> `ARPG_Player::OnRespawned` 里调了 `ClientSetLocation`。

> `AActor::ReplicatedMovement` 是 `COND_SimulatedOnly`，**根本不会发给它**。
> 不显式推一次的话，客户端上的人会"停在死亡地点，过一会儿才被拽回出生点"。

## 4. 调试手册

### 4.1 控制台命令（已核对过引擎注册名）

**打开控制台**：PIE 里按 `` ` ``（波浪键）。

| 命令 | 作用 |
|---|---|
| `AbilitySystem.DebugBasicHUD` | 开关 GAS 基础 HUD（哪些 Actor 有 ASC） |
| `AbilitySystem.DebugAttribute` | 开关属性显示 |
| `AbilitySystem.DebugAbilityTags` | 开关能力标签显示 |
| `AbilitySystem.DebugBlockedAbilityTags` | 显示被阻断的能力标签 ★ 排查"按键没反应" |
| `AbilitySystem.DebugIncludeModifiers` | 属性显示里附带 Modifier 明细 |
| `AbilitySystem.ClearDebugAttributes` | 清掉手动 pin 的属性 |
| `AbilitySystem.DebugDrawMaxDistance` | 调试绘制的最大距离 |

> 💡 老教程里的 `showdebug abilitysystem` 是同一套东西的旧入口。
> 上面这些是引擎里直接注册的控制台命令，按需开关比一刀切更清爽。

### 4.2 打开日志详略

```
Log LogRPG_Ability Verbose      // 能力注册 / 激活 / 失败原因
Log LogRPG_Combat  Verbose      // 伤害结算 / 受击 / 死亡
Log LogRPG_AI      Verbose      // 感知 / 黑板 / 行为树
Log LogRPG_Animation Verbose    // 动画状态
```

关掉：把 `Verbose` 换成 `Display`。

**只想看某一类**：`Log LogRPG_Combat Log`。

### 4.3 症状 → 原因对照表

| 症状 | 先看哪里 | 常见原因 |
|---|---|---|
| **客户端按键没反应** | 客户端日志有没有 `登记输入能力映射：N 条（客户端）` | ① N=0 → 角色蓝图的 `Startup Abilities` 是空的<br>② 有 `已登记映射但拿不到对应的能力实例` → 能力没复制到 / 服务器没授予<br>③ 有 `没有绑定任何能力` → 这个输入标签压根没配 |
| 客户端能攻击但**没伤害** | 服务器日志有没有 `受到 X 点伤害` | 服务器端命中判定没通过（客户端只做预测表现，真实伤害在服务器算） |
| **只有一边看得到受击动画** | 蒙太奇是否在服务器播放 | 受击 GA 是 `ServerOnly`，蒙太奇靠 `RepAnimMontageInfo` 复制 |
| 客户端**看不到敌人血条** | 敌人的 ASC 属性是否复制 | 属性集用的是 `COND_None`，理论上所有人都收得到 |
| 自己头顶**也**有血条 | `IsLocallyControlledPlayer()` 的判定 | 见 ARCHITECTURE 阶段 7 的那个坑 |
| 客户端**复活后位置不对** | `ClientSetLocation` 有没有被调到 | 见 §3.3 的说明 |
| 两端表现不一致 | 先确认你看的是同一个 Actor | 窗口 1 里有两个玩家，别把远程那个当成自己 |
| **一开始正常，过一会儿才不一致** | 大概率是预测回滚 | 看 `Log LogRPG_Ability Verbose` 有没有失败的预测 |

### 4.4 判断"这是不是联机才有的问题"

一条经验法则：

> **如果两端都在报同一件事 → 大概率是逻辑 bug（单机也能复现）。
> 如果只有一端报、或者两端看到的不一样 → 才是联机时序问题。**

联机时序问题的典型特征：**加日志反而看不出来**（因为日志本身也有时序）。
这时候要看的是"**哪个值在哪一端是多少**"，而不是"代码走到哪一行了"。

## 6. 这一阶段**不做**的

| 项 | 为什么 |
|---|---|
| 延迟补偿 / 位置回滚 | L3 范围，明确不做 |
